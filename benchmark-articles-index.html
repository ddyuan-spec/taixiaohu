一、主对标文章（PRD 优化核心参考）

① AI产品经理工作流01：收到一个需求后，我现在会先让AI跑完这套分析流程

  • **链接**：https://mp.weixin.qq.com/s/cKW9DbaqiFghp3e-Fi5SEA
  • **作者 / 来源**：公众号（AI 产品经理工作流系列，作者未署名，-series 01）
  • **全文离线备份**：[benchmark-article-aipm-workflow01.html](benchmark-article-aipm-workflow01.html)
  • **一句话主题**：收到需求后**不要马上写 PRD/画原型**，先让 AI 跑完 **6 步需求分析流程**，把最容易遗漏的部分扫一遍，再进入文档与原型。
  • **为什么它是主对标**：这篇比之前误收的道三「多 Agent 评审」**更贴 PRD 优化**——道三优化的是「PRD 写完后被审得更干净」，而这篇优化的是「**PRD 写之前需求有没有拆透**」，正好填补我们 `requirement-confirm-gate` / `requirement-workflow` 的前置环节。

可仿写的 6 步需求分析流程（结构即方法论）

  1. **还原真实问题**：别接受当前方案，区分"问题 vs 方案"，还原业务方真实目标，给出其他解决路径。
  2. **识别用户角色**：输出角色表（名称 / 目标 / 使用频率 / 关注信息 / 操作权限 / 与其他角色关系）。
  3. **拆具体场景**：每个场景含（场景名 / 触发时机 / 用户当前状态 / 想完成什么 / 系统应提供帮助 / 优先级）。
  4. **梳理业务流程**：按步骤拆解，标注触发者、系统判断、输入/输出、状态变化，多角色用泳道图思路。
  5. **异常与边界场景扫描**（8 类）：用户操作异常 / 系统状态异常 / 数据异常 / 权限异常 / 网络接口异常 / 并发重复 / 历史数据兼容 / 后台处理异常 → 表格输出（异常场景 / 触发条件 / 影响 / 产品处理建议）。
  6. **模拟需求评审**：扮演资深研发 / 测试负责人 / 业务负责人，各提 ≥10 个尖锐问题，最后总结当前最大 5 个风险。

可直接复用的资产（已存全文，含可直接复制的完整 Prompt + 需求分析 Checklist）

  • **完整 Prompt**：让 AI 以"10 年资深产品负责人"身份，按「真实问题分析 → 角色分析 → 场景拆解 → 流程梳理 → 异常边界 → 模拟评审 → 最终输出（是否清晰/最大风险/补充信息/能否进 PRD）」七段输出。
  • **需求分析 Checklist（10 问）**：收到需求后先问自己 10 个问题，覆盖真实问题、角色、场景、流程、异常、评审六个维度。
  • 跑完这套流程通常得到 5 样东西：真实问题 / 角色清单 / 场景拆解 / 业务流程 / 风险问题——据此写 PRD「不再是硬憋」。

A. PRD 评审优化（多 Agent 并行评审）

② WorkBuddy专家团：实现多 agent 协作【需求评审】，只要这几步！

  • **链接**：https://mp.weixin.qq.com/s/tVOEfm7oAoKvES9WNJnwpQ
  • **作者**：道三（微信公众号）
  • **全文离线备份**：[benchmark-article-multiagent-review.html](benchmark-article-multiagent-review.html)
  • **要点**：用 WorkBuddy「专家团（Team）」让测试/前端/后端 Agent **并行**审同一份 PRD，汇总出**带角色颜色 + 严重度排序**的 HTML 评审报告。结构化 JSON 输出、待确认项汇总、≤3 轮迭代复审。
  • **与我们的关系**：优化「PRD 写完后被审得更干净」，与 `pm-review-board`（六角色评审）/`pm-master`（总控）高度同构；可借鉴点=结构化 JSON 协议 + 颜色编码报告 + 并行 Team 编排 + 迭代复审。详见旧版索引分析（已并入本库历史）。

B. 公众号写作技巧（聊天体）

③ 写文2小时，阅读25，改成"聊天体"后，直接进流量池

  • **链接**：https://mp.weixin.qq.com/s/O7ND3FqQg55k0M4QXOSeng
  • **作者**：礼礼（公众号）
  • **全文离线备份**：[benchmark-article-chat-style.html](benchmark-article-chat-style.html)
  • **要点**：公众号"聊天体"写作六法——①把"我"带进来（由我到你，抛话题引共鸣）②拒绝爹味说教（作者没有智力优越感才给读者愉悦感）③适当留白（别把话说尽，别把读者当傻子）④多用短句少长句（一段不超手机三行，有呼吸感）⑤放弃高级词汇（大白话，别堆成语制造距离感）⑥多提问调动参与感（"你们觉得呢"把单向传递变互相探讨）。
  • **已固化**：该六法已写入 `wechat-write` skill 的「聊天体写作法」风格层，作为公众号文案生成时的强制风格约束与自检项。

C. 公众号发布自动化（打通后台·进草稿箱）

④ 实测WorkBuddy打通公众号！文章自动进草稿箱！

  • **链接**：https://mp.weixin.qq.com/s/lWpQsCJ1bgAiX-229AGOMw
  • **作者**：晓庄（公众号「晓庄AI创业笔记」）
  • **全文离线备份**：[benchmark-article-draft-box.html](benchmark-article-draft-box.html)
  • **一句话主题**：把「写稿 → 排版 → 推送草稿箱」做成流水线，用微信官方 API（`media/upload` 素材 + `draft/add` 草稿）自动进草稿箱，排版环节归零；并固化"晓庄风格"解决 AI 味。
  • **核心方法论（已提炼为可固化点）**：
  1. **后台打通前置**：微信开发者平台（2025-12-01 起旧路径失效）→ 我的业务 → 公众号 → 开发密钥，拿 AppID/AppSecret + 加 API IP 白名单（WorkBuddy 原生连接填它给的 IP）。
  2. **微信兼容排版**：`<table><tr><td>` 容器骨架，样式全打在 td，仅允许 `color/background-color/font-size/font-weight/padding/margin/border/text-align/line-height`，禁用 `border-radius/position/linear-gradient/伪元素`；克制用框。
  3. **字节校验**：标题 ≤64 字节、摘要 ≤120 字节（中文 3 字节），超长报 45003/45004。
  4. **风格固化 4 步**：投喂 3-5 篇 → 学全部历史文章 → 建《写作规范》风格库 → 封装成 Skill（我们已通过 `wechat-write` + 聊天体六法覆盖第 4 步）。
  5. **发布前 5 步审核门禁 + 反馈回流**：内容方向 / 像不像你 / 标题 / 排版 / 截图；每轮只改一个维度，4-5 轮后把反馈写回风格库/Skill。
  • **已固化**：该文能力已增强进 `wechat-article-pro` skill（v2.0.0），新增：① `scripts/wechat_format.py` 本地排版转换器（table 容器 + 样式白名单 + 字节校验）② `scripts/push_to_draft.py` 推送参考实现（media/upload + draft/add）③ 自动推送草稿箱 workflow（AppID/AppSecret/IP 白名单 + 安全红线）④ 发布前 5 步审核门禁 + 反馈回流。原 skill 伪"自动"（手动浏览器点击）已替换为真推送流程。

四、分析总览：这些对标能不能优化我们的 PRD / 写作输出？

结论：能，且分两层——

  • **需求拆透层（主对标①）**：cKW9 的 6 步流程直接补强 `requirement-confirm-gate`/`requirement-workflow`，让进入 PRD 前的需求分析标准化、可复用（尤其第5步异常扫描与我们的 PRD 异常红线强对齐）。**优先级最高（P0）**。
  • **评审清洗层（参考②）**：道三的多 Agent 并行评审优化「PRD 写完后被审干净」，与 `pm-review-board` 同构，增强点在结构化 JSON + 颜色报告 + 迭代复审（P1）。
  • **写作表达层（参考③）**：聊天体六法已固化进 `wechat-write`，提升公众号文案可读性与流量表现（已落地）。

风险提示

  • cKW9 / 道三 两篇都是「方法论/工作流」设计稿，**不是 PRD 内容写作模板**；我们 PRD 章节结构仍以你桌面《PRD 输出规范（修订于260715）》「一~九」为准，别被它们的骨架带偏。
  • 聊天体适合公众号/对外表达；**PRD 文档本身应保持结构化、严谨**，不要把"聊天体"套进 PRD（PRD 用标准章节 + 待确认占位即可）。
