二、项目背景与目标

当前「券规则说明」(rule_desc) 由运营在新建券时纯手填富文本，存在口径不统一、易漏写（漏写叠加/适用商品/端口/有效期）、表述随意等问题。本期目标：在新建券（D2）表单中提供「自动生成券规则」能力，系统依据同页已填的优惠规则、叠加方式、适用商品、适用端口、有效期，按固定模板自动拼出标准规则说明并回填至「券规则说明」富文本，运营可在此基础上二次编辑。

KPI / 预期效果：券规则说明填写完整率提升、口径统一、运营效率提升；本期无独立量化 KPI，沿用优惠券体系整体指标。

2.1 需求范围

维度范围
涉及页面平台端后台 · D2 新建券页（新增「规则自动生成」按钮 + 回填逻辑）；D1 券详情页（展示逻辑不变，仅补充内容来源说明）
涉及字段cpFullAmt / cpCutAmt / cpLadder / cpStepLimit（优惠力度）；cpShare（叠加）；cpProd + 已选商品（适用商品）；cpPort（端口）；cpTimeType + cpStart/cpEnd/cpValidDays（有效期）；rule_desc（回填目标）
端口范围仅平台端后台；C 端（App/H5/小程序）券规则页取 rule_desc 不变
本期不涉及券类型扩展（本期仍为满减券，固定只读）；发券活动 D3；历史已建券的批量重生成（二期待定）

三、业务流程与架构（流程图 + 信息架构 + 状态机）

信息架构：本期改动集中在平台端后台「优惠券管理 → 新建优惠券」页面，C 端及其他后台模块无变化。状态机：沿用优惠券模板既有状态机（启用/下架/删除），本期不新增状态。

本需求为 D2 新建券页增量改动，核心流程如下：

  1. 运营进入 D2 新建券页，填写优惠规则、叠加、商品、端口、有效期等字段；
  2. 运营点击「自动生成券规则」按钮；
  3. 前端校验关键字段完整性；
  4. 按 §4.2 模板拼接头部 H + D1~D5 + 尾部 T；
  5. 若「券规则说明」已有内容，弹覆盖确认；确认后回填富文本；
  6. 运营可二次编辑；提交后 rule_desc 落库；D1 详情页展示该富文本内容。

涉及终端明细：仅平台端后台；C 端三端仅读取 rule_desc，本期无新增页面/接口。

需求影响范围：D2 新建券页（新增按钮+回填逻辑）、D1 券详情页（展示来源说明补充）、正式 PRD §4.1.3 字段表更新。

4.2 自动生成模板与字段取值映射（核心）

拼接顺序固定：头部 H → D1 优惠力度 → D2 叠加规则 → D3 适用商品 → D4 适用端口 → D5 有效期 → 尾部 T。每个动态段按「前缀 + 变量 + 后缀」拼接；变量缺失则该段整段省略。

片段取值来源（券模板新增字段）拼接规则（前缀+变量+后缀）示例
头部 H
(固定)		无（系统常量）固定文案 【泰小虎优惠券使用规则】【泰小虎优惠券使用规则】
D1 优惠力度cpFullAmt(X) / cpCutAmt(Y)；阶梯时 cpLadder + cpStepLimit(N)单档：前缀「本券为满减券，订单满」+X+「元减」+Y+「元（仅可减 1 次）。」
阶梯：前缀「本券为满减券，订单每满」+X+「元减」+Y+「元，最多可减 」+N+「 次。」		单档：本券为满减券，订单满99元减20元（仅可减 1 次）。
阶梯：本券为满减券，订单每满300元减100元，最多可减 3 次。
D2 叠加规则cpShare 勾选项：zhenxiang_points→臻享积分 / multi_box→多盒多折 / multi_use→多张本券全空：固定「本券为独立优惠，不可与臻享积分、多盒多折等其他优惠共用，且不可叠加多张使用。」
非空：前缀「本券可叠加：」+ 勾选项中文名（、连接）+「。」		空：本券为独立优惠，不可与臻享积分、多盒多折等其他优惠共用，且不可叠加多张使用。

spec：前缀「本券仅限以下商品使用：」+ 商品名(、连接)+「（共 N 件）。」

spec：本券仅限以下商品使用：红门灵芝胶囊、泰山黄芪片（共 2 件）。
D4 适用端口cpPort 勾选项：app→泰小虎App / h5→泰尔超优惠H5 / mini→泰尔超优会小程序全选(3)：固定「本券在泰小虎App、泰尔超优惠H5、泰尔超优会小程序均可使用。」
部分选：前缀「本券仅可在」+ 端口名(、连接)+「使用。」		部分：本券仅可在泰小虎App、泰尔超优惠H5使用。
D5 有效期cpTimeType(fixed/after) + cpStart~cpEnd 或 cpValidDays(N)fixed：前缀「本券有效期：」+ 开始日期 +「 至 」+ 结束日期 +「。」
after：前缀「本券自领取之日起 」+ N +「 天内有效。」		fixed：本券有效期：2026-08-01 至 2026-12-31。
after：本券自领取之日起 24 天内有效。

五、非功能性需求（含埋点）

项说明
生成结果长度自动生成文本纯文本长度须 ≤ 2000 字（与 rule_desc 校验一致）；超限则截断并提示。
性能生成逻辑纯前端，无后端接口请求，点击后即时回填。
二次编辑生成回填后运营可自由增删文字/插图片，提交时存 rule_desc（既有逻辑不变）。
幂等多次点击「自动生成」以当前表单最新值重新拼装覆盖；不累积。
埋点需求本期不新增埋点事件。埋点规范在线地址：https://ddyuan-spec.github.io/taixiaohu/taixiaohu-tracking-spec.html（引用既有 30 事件目录；本期无新增事件，故不引入事件表）。

六、验收标准

#验收项
1新建券页出现「自动生成券规则」按钮，位于「券规则说明」上方
2填写满99减20/全部商品/仅App/固定有效期 → 点击生成 → 富文本出现符合 §4.2 模板的标准文案
3勾选「阶梯优惠券」→ 生成文案为「每满 X 减 Y，最多可减 N 次」
4「可共用优惠」全空 → 生成「独立优惠」文案；勾选项 → 「可叠加：xxx」
5「商品选择」指定/排除 → 生成对应商品清单文案
6「券可使用端口」全选/部分 → 生成对应端口文案
7「有效期」固定/领取后 → 生成对应有效期文案
8富文本已有内容时点击生成 → 弹覆盖确认；确认后整体覆盖
9必填生成项缺失（如未填满减/未选商品）→ 不生成并提示对应文案
10生成后运营可继续编辑，提交后 D1 详情页正确展示

七、关键边界设计检查清单

检查项结论
生成文本是否会超出 2000 字限制已按 ≤2000 字设计，超限自动截断
运营二次编辑后是否会被再次生成误覆盖二次点击生成时弹确认，确认才覆盖
阶梯券与单档券文案是否区分是，阶梯含「每满…最多 N 次」
是否影响 C 端展示仅 rule_desc 内容变化，C 端无改动
是否影响既有券实例仅新建券模板时生成，历史券模板 rule_desc 不变
