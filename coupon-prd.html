二、项目背景与目标

2.1 业务背景（痛点）

现有优惠券体系仅支持最基础的券模板配置，缺少对营销活动的支撑：无法按用户行为（直播观看时长、支付完成、签到等）自动发放券，缺少独立领券活动配置，客户端也缺失"系统发券触达"的获券弹窗。运营需在多个系统间手工操作，券的发放-领取-核销全链路未打通，数据无法回溯。

2.2 项目目标

  • 后台双端：平台端 + 商家端均可配置券、发券活动（规则引擎）、领券活动，数据按店铺隔离。
  • 发券规则引擎：支持 7 类触发源 + 动态阈值 + 会员等级限定 + 多券模板关联 + 每人每种限发上限。
  • 客户端获券触达：App / 小程序 / H5 在触发条件满足时弹出"获券弹窗"，支持多张券（每种 1 张）。
  • 客户端用券闭环：我的优惠券（三态）、商品详情领券、确认订单选券 + 底价保护核销。

2.3 衡量指标（KPI）

指标定义目标（示例）
总发放量活动/手动发放券张数环比 ↑ 12%（看板可观测）
核销率已核销 / 已领取≥ 60%
核销金额用券抵扣总金额环比 ↑ 8%
活动进行中数发券 + 领券活动进行中计数看板实时
⚠️ 目标值为示例，具体 KPI 阈值 @干系人 确认。

5.2 性能 / 安全 / 兼容

  • 性能：券列表 / 活动列表分页（10/20/50/100/200/500）；获券弹窗下发异步，不阻塞主流程。
  • 安全：领券活动防刷（同设备/IP 限领）；发券规则引擎防重发（按用户+活动+券模板去重，每人每种限发上限）。
  • 兼容：App（iOS/Android）、微信小程序、独立 H5（移动浏览器）；后台 Chrome/Edge 最新版。
