二、项目背景与目标

2.1 业务背景（痛点）

现有优惠券体系仅支持最基础的券模板配置，缺少对营销活动的支撑：无法按用户行为（直播观看时长、支付完成、签到等）自动发放券，缺少独立领券活动配置，客户端也缺失"系统发券触达"的获券弹窗。运营需在多个系统间手工操作，券的发放-领取-核销全链路未打通，数据无法回溯。

2.2 项目目标

  • 后台双端：平台端 + 商家端（为范围内）均可配置券、发券活动（规则引擎）、领券活动，数据按店铺隔离。
  • 发券规则引擎：支持 7 类触发源 + 动态阈值 + 会员等级限定 + 多券模板关联 + 每人每种限发上限。
  • 客户端获券触达：App / 小程序 / H5 在触发条件满足时弹出"获券弹窗"，支持多张券（每种 1 张）。
  • 客户端用券闭环：我的优惠券（三态）、商品详情领券、确认订单选券/核销。

2.3 衡量指标（KPI）

指标定义目标（示例）
总发放量活动/手动发放券张数环比 ↑ 12%（看板可观测）
核销率已核销 / 已领取≥ 60%
核销金额用券抵扣总金额环比 ↑ 8%
活动进行中数发券 + 领券活动进行中计数看板实时

功能说明：App 端商品详情页新建「领券」入口与领券交互流程。用户在商品详情页可查看该商品关联的可领优惠券，点击领取后写入用户券包。

要素说明
入口位置商品详情页价格区域下方，展示为横向可滑动券列表（或折叠条「领券立享 新人立减15元 ▸」）
列表内容展示该商品可领的券：券名 / 面额 / 门槛 / 领取按钮
已领取的券显示「已领取」（灰色禁用态）防重复领取
点击「立即领券」1. 调用领券接口（传入 user_id + activity_id + coupon_template_id）
2. 接口返回成功 → 弹出领取成功弹窗：「已放入卡包」+ 券面额提示
3. 弹窗提供两个按钮：「立即购买」（跳确认订单，自动选中该券） / 「查看我的券」（跳我的优惠券页）
4. 接口返回失败 → toast 提示失败原因（「已领完」/「已达限领张数」/「活动已结束」）
限领规则每张券每人限领 N 张（取《领券活动表》limit_per_user 字段）；超限后按钮置灰显示「已领完」
数据来源进入商详时调用接口查询该商品(spu_id)关联的《领券活动》+《券模板》，返回可领券列表

前置条件：用户已登录；商品存在关联的领券活动且活动在有效期内。

权限：所有登录用户可领；未登录用户点击领券触发登录引导。

异常分支：

  • 活动已结束 → 领券按钮隐藏或显示「已结束」
  • 库存发完 → 显示「已抢光」
  • 网络异常 → toast「网络异常，请重试」，按钮允许重试
  • 重复领取 → 接口幂等返回已有券信息，前端显示「已领取」

4.3.5 确认订单选券 / 核销本期新增

功能说明：App 端确认订单页新建「选券」区域与核销逻辑。用户下单时可选择适用的优惠券抵扣，提交支付成功后选中券自动核销。

要素说明
入口位置确认订单页价格摘要区域，展示为「优惠券」可折叠行（默认展开）
可用券列表1. 进入确认订单时，后端根据订单金额（商品总价）筛选用户未使用券中满足门槛的券
2. 列表展示：券名 / 面额 / 门槛 / 有效期 / 单选 Radio
3. 默认选中「推荐」券（抵扣金额最大的那张），标记「推荐」标签
4. 也可选择「不使用优惠券」
选券计算选中券后实时重算：
- 应付金额 = 商品总价 - 券面额
- 展示优惠明细：原价 ¥XX - 券抵扣 ¥YY = 实付 ¥ZZ
提交订单1. 用户点「提交订单」（或「立即支付」）→ 前端校验库存/地址等既有逻辑 + 校验所选券仍有效（未过期/未达上限/未被他人场景抢占）
2. 调用创建订单接口（传入 selected_coupon_id）
3. 后端创建订单并预占该券（状态从「未使用」→「已预占」）
4. 跳转收银台支付
支付成功 → 核销支付网关回调成功后：
1. 后端将券状态置为「已使用」（核销）
2. 写入《核销流水表》（order_id / user_id / coupon_id / redeem_amount / redeem_time）
3. 前端 toast 提示「已抵扣 ¥XX」
支付失败 / 取消券状态从「已预占」回退为「未使用」（释放供下次使用）；不扣减
数据来源可用券列表：调用接口查《用户券表》（status=未使用 + end_time>now + 门槛≤订单金额）
核销流水：写《核销流水表》

前置条件：用户已登录；购物车/商品已加入待结算；用户持有至少 1 张未使用券且满足当前订单门槛。

权限：仅本人可选本人的券。

异常分支：

  • 所选券在支付前过期 → 提示「优惠券已过期」，自动移除，重新计算价格
  • 所选券在支付期间被其他订单抢占（并发）→ 后端返回冲突，前端提示「优惠券已被使用」，刷新可用券列表
  • 订单含不可用券的商品（适用范围不匹配）→ 该券不在可用列表中出现
  • 退款场景 → ⚠️ 不做售后退券（规则写死）：全额/部分退款券均不退；仅两种返还场景——未支付取消订单、后台关闭订单——均为已有功能无改动
