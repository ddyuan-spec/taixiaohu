二、项目背景与目标

2.1 业务背景

泰小虎 App 用户在健康场景下缺乏围绕睡眠/习惯的低门槛任务闭环。当前首页、我的睡眠、健康打卡等页面相互独立，缺少把「睡眠数据→任务推荐→打卡完成→分享激励」串起来的主线，导致用户打卡动力不足、健康档案行为数据缺失。

2.2 项目目标

  • 用户目标：每日获得睡眠日报提醒，领取并完成轻量健康任务，获取虎力值，养成连续记录习惯。
  • 业务目标：提升 App DAU、健康打卡完成率、健康档案行为字段完整度；通过分享传播获取自然增量。
  • 运营目标：后台可配置任务模板、候选任务池、固定首批规则，支持无需发版调整 C端任务策略；弹窗类（每日完成弹窗、分享海报）文案与样式本期前端写死，不配置后台。

三、业务流程与架构

3.1 业务流程图

横向泳道：用户端 / 服务端 / 平台端后台。

上图为三泳道业务流程架构：用户端动作（收 PUSH → 进首页/睡眠 → 领取打卡 → 完成分享 → 得虎力值）由服务端任务引擎驱动，服务端按后台配置的「任务模板 / 候选池 / 固定首批规则」下发任务并回流数据至后台监控。

涉及终端：用户端（Android / iOS App）+ 平台端后台（任务模板、候选池、规则，以及「每日任务重置」与「PUSH 推送」两个独立定时任务的配置）。

两个相互独立定时任务：① 每日 03:00（凌晨三点）执行任务重置——批量将用户昨日未完成任务置为过期、连续天数清零、生成新日实例；② 每日 08:00（早上八点）执行PUSH 推送——按用户当日状态四分支推送健康打卡晨报。两者分属不同定时任务，不可合并为同一时点。

主流程：

  1. 服务端在每日 08:00（早上八点）向目标用户推送健康打卡晨报 PUSH；PUSH 内容按用户当日状态四分支判定，与每日 03:00 任务重置相互独立；
  2. 用户点击 PUSH/锁屏通知按分支进入对应页面（首页 / 健康打卡页 / 开屏引导 / 领取任务页）；以「有睡眠数据」分支为例，进入 App 首页后首次弹窗提示「睡眠日报已生成」；
  3. 用户可点击弹窗进入「我的睡眠」查看睡眠数据与任务卡片；
  4. 任务卡片引导用户进入「健康打卡」或「开启健康打卡」；
  5. 用户在「开启健康打卡」页选择 1~5 个任务加入当日任务列表；
  6. 用户在「健康打卡」完成任务（有详情页则先进 H5 详情，无详情则点击直接完成）；
  7. 首次完成任务后弹出「太棒了」完成弹窗，用户可分享或继续开启健康打卡；
  8. 完成当日全部任务且分享一次后，虎力值一次性发放至「虎力值任务中心」；仅完成任务不发放、未分享亦不发放。

3.1.1 异常与分支流程

  • 未授权推送：用户关闭系统通知权限或不授权推送时，本 PUSH 不再发送；用户仍可主动进入 App 查看睡眠日报与任务，不受影响。
  • 未登录态：点击 PUSH/通知任意区域先跳转登录页，登录成功后回跳首页并继续首屏流程（非重新操作）。
  • 无睡眠数据：服务端未生成当日日报（用户无睡眠记录）时，不弹「健康日报」弹窗，首页任务卡片与任务列表正常展示。
  • 任务过期：到达每日重置时点仍未完成的任务置为过期，不可再完成；断签（T+1 未完成打卡）则连续天数清零（断签判定见 3.3.2）。
  • 网络异常：任务完成操作本地排队，恢复网络后自动补上报（详见 §七 边界清单）。
⚠️ 待确认 @产品/研发：PUSH 触发时区基准、每日首任务完成弹窗是否强打扰、分享后是否带回增量虎力值。

3.3.3 打卡天数与虎力值发放规则

本期将「打卡天数」与「虎力值」两项激励解耦：

  • 打卡天数：完成当日全部任务并分享后，系统记为当天打卡成功，累计打卡天数 +1；连续打卡天数按自然日连续有打卡计算，断签（T+1 未完成）清零重计（本期不支持补卡）。打卡动作仅在分享时触发一次，仅完成任务不记打卡。
  • 虎力值：任务完成时不即时发放，仅累加至「待发放」；须完成当日全部任务且分享一次后，由分享动作一次性发放到账；未完成全部任务或未分享均不发放。
  • 连续打卡额外奖励：连续完成每日任务并分享达到 X 天（默认 7，⚠️ 待确认 @产品）时，由系统一次性发放额外虎力值（默认 +10，⚠️ 待确认 @产品），作为连续习惯成就激励；该奖励独立计入《虎力值账户表》，发放时机 ⚠️ 待确认（达成瞬间直接到账 / 或随当次分享一并发放）。连续中断（T+1 未打卡）后 X 天计数重新累计，已发放奖励不回退。
说明：打卡与虎力值均以「完成任务并分享」为触发点，但二者解耦——打卡按每日一次记录当天是否完成（连续天数随之累计），虎力值则按各任务奖励之和在分享时一次性发放；即便当天完成并分享，打卡仅记 1 次，虎力值按任务累计。

4.1.10.6 按钮逐步逻辑与异常分支

微信好友：

  1. 用户点击「微信好友」；
  2. 前端调用 App 分享 SDK（WeChatShare），传入分享标题、描述、缩略图、落地页链接；
  3. 若分享成功回调：调用服务端虎力值发放接口，将当日 pendingHuLi 一次性转为到账虎力值，toast「虎力值已到账 +N」；
  4. 若分享失败/取消：关闭 SDK 页面，弹窗保持打开，不发放虎力值；
  5. 若未安装微信：toast「未安装微信」。

保存本地：

  1. 用户点击「保存本地」；
  2. 前端将海报容器渲染为图片（html2canvas / 原生截图），调用系统相册保存接口；
  3. 保存成功后：同微信好友成功回调，发放虎力值并 toast「虎力值已到账 +N / 已保存到相册」；
  4. 保存失败：toast「保存失败，请检查存储权限」；不发放虎力值；
  5. 用户拒绝存储权限：首次提示「保存图片需要存储权限」，再次拒绝则不弹权限引导。

取消：

  1. 用户点击「取消」或点击遮罩；
  2. 弹窗执行退场动效后关闭；
  3. 不触发任何奖励发放。

  • 传输安全：所有健康打卡、睡眠记录、任务数据接口强制 HTTPS + 鉴权 Token，禁止明文传输。

六、验收标准

  1. AC1 任务领取：Given 用户无任务，When 进入开启健康打卡页，Then 展示 5 个候选任务，支持多选与换一批。
  2. AC2 任务完成：Given 用户有已开启健康打卡，When 点击无详情任务，Then 任务状态变为已完成，虎力值进入待发放（pending）；完成全部任务并分享后一次性到账。
  3. AC3 详情任务：Given 用户领取了有详情任务，When 点击任务，Then 进入任务详情，点击「立即参与」后完成任务。
  4. AC4 每日首完成弹窗：Given 用户当日首次完成任务，When 完成动画结束，Then 弹出「太棒了」弹窗，支持分享或继续开启健康打卡。
  5. AC5 后台状态机：Given 任务模板为草稿，When 点击上线，Then 状态变为上线；Given 上线状态，Then 仅可下线，不可编辑。
  6. AC6 固定首批规则：Given 用户命中某标签，When 进入开启健康打卡页，Then 首批推荐包含该标签规则下的固定任务（最多3个）。
  7. AC7 每日完成弹窗：Given 用户每日首次完成任务，When C端弹出每日完成弹窗，Then 展示前端写死固定文案与样式（无后台配置）。
  8. AC8 候选任务池：Given 运营将任务移出候选池，When 新用户进入开启健康打卡页，Then 不再展示该任务。
  9. AC9 弱网/断网：Given 用户断网点击完成任务，When 恢复网络，Then 本地排队任务自动补上报，状态正确置为已完成。
  10. AC10 未登录：Given 用户未登录，When 点击任务/领取，Then 拉起登录，登录后自动续作原操作。
  11. AC11 并发防重：Given 用户快速连点同一任务，When 触发完成，Then 前端防抖 + 后端日维度幂等，仅计一次虎力值。
  12. AC12 每日重置：Given 到达 03:00 重置时点，When 批量执行，Then 昨日未完成任务置过期、连续天数清零、生成新实例；已发放虎力值不回退。
  13. AC13 首页入口：Given 用户当日无任务，When 进入首页，Then 卡片展示「开启健康打卡」+「去完成」。
  14. AC14 任务详情：Given 用户点击有详情任务，When 进入详情页，Then 展示 H5 内容，点击「立即参与」完成任务并返回打勾。
  15. AC15 分享海报：Given 用户点击完成弹窗/打卡页「分享」，When 拉起分享海报，Then 展示累计打卡天数标题 + 今日任务列表截图 + 下载二维码，并提供微信好友/保存本地/取消。
  16. AC16 PUSH 四分支：Given 服务端每日 08:00 推送，When 用户状态分别为有睡眠数据/有任务/无档案无任务/有档案无任务无睡眠，Then 分别展示对应分支文案并跳转首页/健康打卡页/开屏引导/领取任务页。
  17. AC17 埋点：Given 用户完成领取/完成/分享行为，When 触发，Then 对应事件（task_claim/task_complete/task_share）按 v2.3 规范上报（评审通过后）。

七、关键边界设计检查清单

  • 网络与异常：弱网/断网时，任务完成操作先写本地队列（含时间戳与任务 ID），恢复网络后按序自动补上报；服务端 500 时按钮置为可重试态，用户可手动重试。⚠️ 待确认 @研发 具体重试策略（重试次数 / 间隔）。
  • 登录与游客态：未登录用户点击任务/领取时拉起登录，登录成功后回跳原页面并自动续作（非回到首页重新操作）。
  • 极限值与空状态：任务名超长省略；任务列表为空展示空态引导；无睡眠数据展示「暂无数据」；连续天数、奖励等数值超长做截断 / 保护展示。
  • 版本兼容性：老版本 App 不显示任务入口；后台新配置对老版本不生效（服务端按接口版本下发）。⚠️ 待确认 @研发 最低版本号。
  • 并发与防重：前端按钮点击防抖（防重复提交）；后端对同一用户同一任务同一自然日维度幂等，重复请求仅首次计虎力值。
  • 每日重置：每日 03:00 任务重置批量将用户昨日未完成任务置过期、连续天数清零、生成新日实例（独立于 08:00 PUSH）。已发放虎力值不回退，重置仅让其可重新完成、领取新日实例。
