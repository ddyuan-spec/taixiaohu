二、整体业务流程图（横向泳道 · 赠送 / 扣除 / 查看全链路）

主流程（3 个端口泳道）：① 平台端后台进入「虎力值管理」页（App管理页签下，新增）→ 批量选择人员 → ② 选理由+填统一数量+批量确认赠送或扣除（新增，允许扣成负数）→ ③ 后端 Admin Grant/Deduct API（新增），包裹既有 earn/consume 方法，写入 reason+operator → 写入流水记录 → ④ 赠扣操作记录表（新增，独立于积分流水）+ App 端「我的」页总额自动反映最新值 + 「变动记录」页展示增减数量+时间+理由（增强，原「完成xxx任务」替换为后台选择的理由）。 虚线为数据依赖关系。 虚线为数据依赖关系。

三、时序图 A：批量赠送虎力值（运营 → 后台 → 后端 → 用户可见）

关键点：步骤 3~5 为本期新增（赠送表单 + 提交按钮 + grant API）；步骤 6 复用既有 earn_points 方法，仅 source 设为 'admin'； 步骤 7 流水记录需额外写入 reason（理由）和 operator（操作人）；步骤 10~11 为 App 端增强——变动记录页展示增减数量+时间+理由三列，原「完成xxx任务」文本替换为后台操作时选择的理由。

四、时序图 B：批量扣除虎力值（允许扣成负数，不做余额阻拦）

不校验余额，available -= M（可为负） 6. INSERT point_transactions {source:'admin', points:-M, reason, operator, balance_after} 7. UPDATE user_points SET available = available - M（可为负数） 8. 返回 {success, new_balance} 9. Toast「已扣除 X 虎力值」+ 刷新余额/流水
与赠送的核心差异：扣除不做余额校验，允许扣成负数（用户已确认）。步骤 5 直接调用 consume_points 扣减，available 可为负数； 步骤 6 流水 points 字段存负值（如 -100），balance_after 反映扣后实际余额（可能 < 0）。 后台前端提交前不弹二次确认框（除非后续追加需求），运营自行对金额负责。

五、功能需求清单（FR）

FR-PLT-01 · 平台端-入口与列表（App管理页签）
在「App管理」页签下本期新增「虎力值管理」页。页面主体为赠扣操作记录表：列出每次批量/单笔赠扣操作的记录，字段含 操作时间 / 操作类型（赠送·扣除）/ 操作人员 / 影响用户数（可下钻）/ 变动总虎力值(±) / 理由。支持按操作类型、操作人员、时间范围筛选。新增
FR-PLT-02 · 平台端-批量赠送 / 扣除
列表上方提供「批量赠送」「批量扣除」按钮，弹出批量操作面板：① 选择人员——支持按手机号搜索添加、按用户ID（多个用逗号隔开）添加、一键全选、批量导入表格（CSV/Excel）勾选人员；导入区提供「下载导入模板」入口，模板列仅「用户ID / 昵称 / 手机号」三列，每行至少填写一个字段即可（系统按已填字段匹配用户，空白行导入时跳过并提示）；② 选择理由（预设枚举+「其他」自由填）；③ 统一填写数量（每位用户相同的赠/扣值）。确认后生成一条操作记录，并逐用户写入流水。新增
FR-PLT-03 · 平台端-扣除允许负数
批量扣除时不做余额校验，允许扣成负数（后台不阻拦）。批量操作通过 Admin Deduct API（包裹 consume_points，source='admin'）统一扣减所选用户，写入 reason + operator。新增 已确认 Q5。
FR-PLT-04 · 平台端-操作明细下钻
操作记录列表的「影响用户数」可点击，弹出该次操作的明细：展示所影响的用户清单（昵称 / 用户ID / 手机号）及各自获得的虎力值(±)。新增
FR-PLT-05 · 平台端-理由配置与操作人落库
维护预设理由枚举（客服补偿 / 活动奖励补发 / 体验回馈 / 违规处罚 / 系统调整 / 误操作退回 / 其他自由填），供批量面板下拉使用。每次操作记录落库 reason（理由）+ operator（当前后台操作人账号）。新增 ⚠️ 理由是否需后台独立配置页（还是代码写死）见待确认 Q1。
FR-APP-01 · App-变动记录展示理由
现有「虎力值变动记录」页每条记录展示三列信息：增减数量 + 时间 + 理由（不含余额列）。原显示「完成xxx任务」的记录，统一替换为后台操作时选择的理由文本（如「客服补偿」「活动奖励」等）。增强
FR-APP-02 · App-虎力值总额实时刷新
「我的」页虎力值总额进入页面时拉取服务端最新值（非本地缓存）。确保后台赠扣操作后用户再次进入即可看到正确金额。增强 ⚠️ 是否需 WebSocket 主动推送见待确认 Q4。
