一、整体业务流程图（横向泳道 · 制券 → 核销全链路）

主流程：① 制券（平台端新增制券能力；商家端已有、拓展使用限制）→ ② 券管理（查看/下架，已有）→ ③ 发券/领券配置触发发券引擎（平台端：直播时长发券【写死规则】+ 指定发券【扩展店铺/商品】；商家端：规则发券活动）→ ④ 直播时长发券调用火山引擎拉取直播进入/退出时间，相减得时长，筛选 ≥X 用户列表 → ⑤ 批量发券入用户券账户 → ⑥ 三端触达（获券弹窗/消息中心）→ ⑦ 领券/持券（商详领券、我的优惠券）→ ⑧ 下单选券 → ⑨ 核销；退券不做售后逻辑，仅保留已有的「未支付返还 / 后台关单返还」。虚线为数据/依赖关系（券模板、领券活动供商详展示、看板取数）。

二、时序图 A：直播时长发券（平台端 · 本期核心新增链路）

本期直播时长发券为写死规则：不提供活动配置化能力，仅实现「取某时间段直播进入/退出时间 → 相减求时长 → 筛选超过 X 的用户列表 → 批量发券」链路。第 3/4 步依赖火山引擎接口，需确认接口能返回哪些数据（进入/退出时间粒度、多次进出是否累计、用户标识与业务账号的映射）。

三、时序图 B：商详领券 → 下单核销 → 关单返还（用户端三端）

不返还优惠券（规则写死）
三端共用同一链路：小程序 / H5 的 2-11 步为已有功能（本期仅新增获券弹窗触达）；App 为全链路新增（商详领券、我的优惠券、下单核销）。返还仅两种既有场景：未支付取消、后台关闭订单——均为已有功能无改动；不做售后退券，规则写死。
